Screen contracts

Built around the task.

Brand expression at entry.
Clarity wherever money changes.

A useful first minute

Welcome → choose storage → create an account → record a transaction. Local use has no forced sign-in or purchase. Cloud and self-hosted options explain where data goes.

Local-first does not currently mean automatic offline cloud sync. Browser data does not silently appear in native storage.

Four destinations. One action.

Overview, Transactions, Plan and More are the proposed destinations. Add transaction is a distinct action. A tablet gains a rail and meaningful list/detail panes.

Native back, keyboard, safe area, resume and assistive technology need real-device evidence.

A complete screen includes failure

Put empty, loading, offline, permission denied, unsaved, save failed and recovery states beside the success state. A payment screen also needs restore and existing-subscriber paths.

A generated frame is an idea. An accepted surface includes real content, state behavior and accessibility checks.

Commercial decision

Count what remains.

Customer revenue ≠ proceeds ≠ profit.
Tax, fixed fees and purchase route matter.

The proposed starting point is Stripe on the web, native subscriptions for new mobile buyers, and one server-owned entitlement model. Existing web subscribers sign in and retain their plan. Regional external payments need their own fee and compliance calculation.
